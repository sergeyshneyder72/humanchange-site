# ТЗ для разработки: "Капитал здоровья" — MVP

Инструкция к реализации. Экспериментальная версия, целевая аудитория 30–60 лет.

## 1. Онбординг

**Обязательные поля:** возраст, пол, регион (страна/город регистрации).

**Необязательные поля (каждое — независимое, пользователь заполняет любые по своему усмотрению, ничего не блокирует прохождение онбординга):**
- вес (кг)
- рост (см)
- объём талии (см)
- среднее количество часов сна
- обычное время отхода ко сну (если есть устойчивый режим)
- курение — количество сигарет в день (0, если не курит)
- вейп / кальян — факт использования, да/нет (отдельно от сигарет)
- алкоголь — три отдельных поля, объём в мл в неделю:
  - крепкий алкоголь, мл/нед
  - вино, мл/нед
  - пиво и слабоалкогольные коктейли, мл/нед
- физическая активность — минуты/часы активности в неделю, либо количество тренировок в неделю
- наличие серьёзных заболеваний (да/нет + опционально уточнение какое; явно помечено как пропускаемое)

Все поля уточняют только стартовый расчёт (см. п.2). Ежедневно в MVP отслеживаются только курение и спорт (см. п.4).

**Расчёт стартового капитала:**
- Источник — актуарная таблица: SSA Period Life Table (US) либо WHO Global Health Observatory. Fallback на глобальные показатели WHO при отсутствии данных по региону.
- Поправка по сну — U-образная зависимость смертности от продолжительности сна (метаанализ, ~1.5 млн участников): минимум относительного риска в диапазоне **7–8 часов**, риск растёт в обе стороны от диапазона.
  - Точка минимума риска сдвигается вправо для пользователей с высокой физической нагрузкой (сегментация по скользящему среднему минут активности за 2-4 недели: низкая/умеренная/высокая нагрузка → своё окно минимума риска для каждой группы, не единая точка для всех).
- Поправка по алкоголю (по трём категориям отдельно), курению (текущий статус + количество), серьёзным заболеваниям — через известные relative risk / hazard ratio из литературы.
- Вейп/кальян — на MVP-этапе фиксировать только факт использования, без коэффициента (недостаточно устоявшихся данных).
- Заболевания — не показывать резкое падение стартового числа сразу после ответа, подача сглаженная.

## 2. Два графика

**График 1 — "Портфель здоровья".** Накопительная кривая с даты первого запуска, отражает сумму действий пользователя (депозиты/списания от активных факторов, см. п.4). Инфляция ("−1 день за прожитый день") в этот график **не входит** — график реагирует только на реальные действия пользователя, не на течение времени само по себе.

**График 2 — "Экономия на медицине".** Оценка в деньгах ($ или локальная валюта), насколько поведение пользователя снижает ожидаемые расходы на здравоохранение — по аналогии с моделью HealthyCapital (см. общий контекст проекта). **Открытый пункт:** методология перевода дней капитала / конкретных факторов в денежную оценку экономии пока не определена — нужны реальные источники данных по стоимости медицинских услуг/лечения курения и малоподвижности, а не произвольный коэффициент. Не внедрять заглушечную формулу — оставить как явно помеченную задачу перед реализацией этого графика.

**Стартовое число из онбординга** — статичная справочная цифра под заголовком (не график, не пересчитывается).

## 3. Активные факторы MVP (только 2)

Остальные факторы в UI — кнопки/карточки, неактивны (disabled, пометка "скоро").

### 3.1 Курение
- Стоимость: 20 минут капитала за сигарету (≈0.014 дня), источник — UCL (2024/2025, Addiction).
- Возрастной множитель:

| Возраст | Множитель |
|---|---|
| 30 | ×1.0 |
| 40 | ×1.2 |
| 50 | ×1.5 |
| 60 | ×1.8 |

(промежуточные значения — линейная интерполяция)

- Формула: `Списание = Кол-во_сигарет × 0.014 × Множитель(возраст)`

### 3.2 Спорт / физическая активность
- Соотношение: 1 час активности ≈ +3 часа капитала (источник — Spiegelhalter, BMJ 2012, microlife: 20 мин активности = 2 microlife = +1 час капитала). Уточняется — вопрос направлен эксперту напрямую.
- Cap: положительный эффект не растёт после **90 минут** активности в день.
- Формула: `Начисление = min(Минуты_активности / 60 × 3ч, 90/60 × 3ч) / 24`

## 4. Итоговая дневная формула (график "Портфель здоровья")

```
Капитал(день) = Капитал(день-1)
                − (сигареты × 0.014 × множитель_возраста)
                + min(минуты_спорта/60 × 3, 4.5) / 24
```

## 5. Обязательная оговорка в интерфейсе

Рядом с графиком: "Статистическая оценка на основе научных исследований, не медицинский прогноз для конкретного человека."

## 6. Не входит в MVP (заложить архитектурно, не реализовывать сейчас)

- **Новые факторы капитала — два разных источника пополнения списка:**
  - Алкоголь, сон, питание, стресс — добавляются командой напрямую (без голосования), это уже решено.
  - Остальные, менее очевидные факторы — по предложениям пользователей через "Фонд идей" (см. п.10), с порогом голосования (например, 100 запросов на один и тот же фактор).
- Интеграции с носимыми устройствами (Garmin, Apple Health, Oura и т.д.).
- Отдельная логика для возрастов вне 30–60 (версия 2.0).

## 7. UI-элементы

- Число капитала (график "Портфель здоровья") крупно вверху
- Тренд за 7 дней (стрелка + число)
- Кривая графика (SVG/canvas)
- Переключатель периода (неделя/месяц/год) — визуальный для MVP, не обязательно полностью функциональный
- Лента последних операций (депозиты зелёным, списания красным), иконки: курение / спорт
- Карточка "следующий шаг" — одна рекомендация, не список
- Отдельный экран/блок для графика "Экономия на медицине" (см. п.2)

## 8. База знаний (MVP, лёгкая версия)

- Основы по каждому фактору (включая пока неактивные) — короткое объяснение "что хорошо, в каком количестве, почему", со ссылкой на источник (UCL, Lee/Lancet, Spiegelhalter, метаанализ по сну).
- Подборка статей по теме (требует лёгкой редакционной курации).
- Раздел "Что впереди" — витрина будущих факторов и функций, включая прогресс голосования по конкретным пользовательским предложениям (см. п.10).

## 9. Общение (вне MVP — заложить архитектурно)

- Общий чат для всех пользователей.
- Пользовательские чаты — создание своих групп с выбранными участниками.
- VIP-чат(ы) — закрытый доступ по категории пользователя (например, founding members), доступ может быть частью премиального предложения.
- Требования при реализации: обязательная модерация; чужой капитал не показывается в чате по умолчанию.

## 10. Фонд идей (MVP, лёгкая версия)

- Раздел для обратной связи: технические неудобства, предложения новых факторов, общие идеи.
- Отправленная идея видна только автору и команде, не другим пользователям.
- Вкладка "Ваши идеи" — история своих обращений, без возможности редактирования (только новые).
- Авторство фиксируется на стороне команды всегда (приватно от других пользователей, не от нас) — нужно для будущего поощрения активных/полезных авторов (например, доступ в VIP-чат, п.9) и уведомления автора, когда его идея реализована.
- Команда вручную агрегирует похожие заявки и публикует только итоговый счётчик голосования (без раскрытия авторства) — см. п.6 и п.8.

## 11. Служба заботы (MVP)

Отдельная вкладка для обращений пользователя по:
- техническим проблемам,
- вопросам к команде.

Не путать с "Фондом идей" (п.10) — там предложения по продукту, здесь — поддержка и вопросы.

## 12. Юридические документы (обязательно перед публичным запуском)

Требуются как минимум:
- Политика конфиденциальности (Privacy Policy) — особенно важно из-за сбора данных о здоровье.
- Пользовательское соглашение / Оферта (Terms of Service).
- Отказ от ответственности (Disclaimer) — продукт не даёт медицинских рекомендаций, статистическая оценка (см. п.5).
- Политика использования cookie (для веб-версии/PWA).
- Согласие на обработку персональных данных при регистрации.

Тексты этих документов — не входят в этот файл, требуют отдельной юридической проработки (не генерировать самостоятельно как окончательный юридический текст).

## 13. Приём платежей — два параллельных сценария

Платформа — PWA, оплата вне App Store/Google Play (без их комиссии и review). Два независимых сценария оплаты, не взаимоисключающих:

**Сценарий A — международный (основной, целевой рынок).**
- Провайдер: Stripe.
- Требование: Stripe недоступен для аккаунтов, зарегистрированных в РФ — нужно юрлицо в поддерживаемой юрисдикции (например, LLC в США) для открытия аккаунта.
- Валюта: USD.
- Тарифы: помесячно, годовая подписка, ограниченное founding-member предложение (см. финансовую модель, `TAM_SAM_SOM_Kukushka.xlsx`).

**Сценарий B — локальный пилот (РФ/РБ, для быстрой валидации).**
- Провайдер: ЮKassa или Robokassa (обе поддерживают ИП, карты МИР, СБП), либо прямой перевод по реквизитам ИП для первых пользователей без интеграции.
- Валюта: RUB.
- Тарифы (адаптированы под локальный рынок, не совпадают с международными): помесячно 990–1490 ₽, founding member (разово, ограниченно) 9 990–14 990 ₽.
- Назначение — не параллельный источник той же выручки, а быстрая проверка ядра продукта (готовы ли люди платить за механику) до готовности международного сценария A.

**Архитектурно:** ценообразование и валюта должны быть настраиваемым параметром, не хардкодиться — понадобится минимум два прайс-конфига (USD/международный, RUB/локальный), выбор сценария оплаты по региону/языку пользователя.
