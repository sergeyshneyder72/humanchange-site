## 2026-08-08 — MVP core loop приложения

По `TZ_model_capital_zdorovya_MVP.md` собран первый рабочий прототип продукта — отдельно от лендинга, в `/app/`.

**Архитектурное решение:** клиентское приложение без бэкенда (состояние в `localStorage` браузера). В ТЗ backend не специфицирован явно; это сознательное упрощение для первой версии core loop, а не окончательная архитектура — места, где нужен реальный API (отправка идей в Фонд идей, кросс-девайсная синхронизация, агрегация голосов), помечены в коде как `TODO(backend)`.

Собрано:
1. **Онбординг** — обязательные возраст/пол/регион + все опциональные поля из ТЗ, ничего не блокирует прохождение. Стартовый капитал считается один раз, показывается с анимацией.
2. **2 активных фактора** (курение, спорт) — формула из раздела 4 ТЗ.
3. **Один график** — «Портфель здоровья» (SVG, накопительная кривая, тренд за 7 дней, лента операций, переключатель периода). Второй график («Экономия на медицине») сознательно не реализован — методология перевода в деньги в самом ТЗ помечена как открытый вопрос; вместо него — неактивная карточка-заглушка.
4. **База знаний (лёгкая)** — объяснение по каждому фактору + источник, подборка чтения, блок «что впереди».
5. **Фонд идей (лёгкая)** — форма отправки + приватная вкладка «Ваши идеи».

**Найден и исправлен баг** при тестировании: переменная `days` была объявлена в блоке `else if`, а использовалась в соседнем `if` вне области видимости — из-за этого кнопка завершения онбординга не работала (тихо проглатывался `ReferenceError` в обработчике клика). Весь флоу прогнан end-to-end в браузере после фикса.

### Правки расчётной формулы (тот же день, после ревью)

Три изменения по итогам обсуждения:

1. **Курение — устранён двойной счёт.** Число сигарет/день из онбординга стало «ватерлинией» (точкой отсчёта), а не отдельным штрафом к стартовому капиталу. Ежедневно: `(Ватерлиния − Сегодня) × 0.014 × ВозрастнойМножитель` — меньше обычного = депозit, больше = списание, ровно на уровне = нейтрально. Проверено изолированным тестом: при прочих равных 20 и 0 сигарет/день в онбординге теперь дают одинаковый стартовый капитал.
2. **Физическая активность — стала полноценным фактором стартового капитала** (раньше только сдвигала окно сна). Источник: ВОЗ, недостаточно активные люди — на 20–30% выше риск смерти vs достаточно активные (порог ВОЗ — 150 мин/нед квалифицирующей активности). Эффект масштабируется тем же возрастным множителем, что уже применён к курению (1.0→1.8 от 30 к 60 годам) — по данным нескольких исследований разрыв между активными и неактивными растёт с возрастом.
3. **Порог «что считается активностью»** (применяется и к онбордингу, и к ежедневному трекингу) — пульс минимум на 50–60% выше покоя (Cleveland Clinic), практически — тест разговором: можешь говорить, но не петь = засчитывается, свободно поёшь = нет. Добавлено как поясняющий текст в онбординге, у поля ежедневной отметки и в базе знаний.

## Известные допущения / открытые вопросы (не решать без реальных данных)

Явно прокомментировано в коде (`app/app.js`), вынесено сюда для видимости:

- **Таблица дожития** (базовая продолжительность жизни по возрасту/полу) — приблизительная иллюстративная таблица, не выгруженный реальный датасет SSA Period Life Table / WHO GHO. Нужна интеграция реального источника перед публичным запуском.
- **Все коэффициенты корректировок** (сон, алкоголь, курение-статус — удалён, активность, заболевания) — литературные оценки для экспериментального MVP, не выверенный клинический датасет.
- **График «Экономия на медицине»** — не реализован, методология перевода в деньги не определена (см. `TZ_model_capital_zdorovya_MVP.md`, раздел 2).
- **Бэкенд** — отсутствует полностью; Фонд идей, синхронизация между устройствами, реальная агрегация голосов пользователей — архитектурно заложены (`TODO(backend)`), не реализованы.
- Вне MVP по ТЗ и сознательно не тронуты в этой версии: интеграции с носимыми устройствами, общение/чаты (раздел 9), служба заботы (раздел 11), юридические документы (раздел 12), приём платежей (раздел 13).
